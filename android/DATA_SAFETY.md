# Google Play Data safety declaration

Last reviewed: September 15, 2026

Package: `com.rsm.eztrivia`

This file records the declaration submitted to Google Play so the Play Console, privacy policy, Android implementation, and future releases can be kept in sync. It is not legal advice and it must be re-reviewed whenever SDKs or data flows change.

## Why these answers match the app

### Google Mobile Ads and UMP

Android uses Google Mobile Ads SDK 25.4.0 and User Messaging Platform 4.0.0. The banner is requested only when UMP reports that ads may be requested and the player does not own Remove Ads. Google's Mobile Ads Data safety disclosure for 25.4.0 says the SDK automatically collects and shares IP address (used to estimate general location), user product interactions, diagnostics, and device/account identifiers for advertising, analytics, and fraud prevention. Google states that this data is encrypted in transit.

References:

- https://developers.google.com/admob/android/privacy/play-data-disclosure
- `android/app/src/main/java/com/rsm/eztrivia/ads/AdConsentManager.kt`
- `android/app/src/main/java/com/rsm/eztrivia/ads/AdBanner.kt`

### Google Play Games Services

Google Play Games is optional. Core trivia works without Play Games. When available, Play Games handles platform authentication, achievements, leaderboards, and private Saved Games synchronization. EZ Trivia submits gameplay scores/progress and reads/writes the private saved-game snapshot; Google may process gamer identity/account information, device identifiers, game activity, achievements, rankings, and saved progress under its Play Games terms. This is why the identity/gameplay categories are marked optional rather than required.

References:

- `android/app/src/main/java/com/rsm/eztrivia/playgames/PlayGamesManager.kt`
- `android/app/src/main/java/com/rsm/eztrivia/playgames/PlayGamesSavedStateManager.kt`
- https://support.google.com/googleplay/answer/3129346

### Google Play Billing

The one-time Remove Ads product is optional. Google Play Billing provides product/purchase ownership information to the app. EZ Trivia stores only a local entitlement flag and sends the purchase token back to Google Play when acknowledging an owned purchase; it does not operate a purchase backend and does not receive card, bank-account, or other payment credentials. Purchase history is therefore declared as optional app-functionality data, while payment-card/bank data is not declared.

Reference: `android/app/src/main/java/com/rsm/eztrivia/billing/RemoveAdsBillingManager.kt`

### First-party behavior

EZ Trivia has no developer-run Android account/profile backend and no first-party analytics or crash-reporting SDK. Gameplay progress is local-first. A question report opens the user's email client with a prefilled draft; nothing is transmitted by EZ Trivia unless the user chooses to send that email.

Reference: `PRIVACY.md`

## Automation details

`Scripts/configure_play_data_safety.py` downloads Google's current public Data safety CSV sample, clears every example response, applies only EZ Trivia's declaration, validates the result, and optionally submits it through the Publisher API.

As of this review, Google's public sample CSV contains 763 rows but the live Publisher API also validates newer account/deletion questions that are absent from that sample. The generator adds those current account/deletion rows when missing, yielding 783 rows. This behavior was discovered from the API validation response and verified by a successful 204 submission.

`.github/workflows/play-data-safety.yml` is intentionally **manual only** (`workflow_dispatch`). A repository push must never silently replace the production Play declaration. Re-run it only after reviewing the current Android SDKs, this document, the privacy policy, and Google's current Data safety guidance.

Google documentation:

- Data safety form: https://support.google.com/googleplay/android-developer/answer/10787469
- Android Publisher Data safety API: https://developers.google.com/android-publisher/api-ref/rest/v3/applications.dataSafety

## Release rule

Before every production release that changes advertising, Play Games, billing, identity, analytics, diagnostics, storage/sync, or another SDK that handles user data:

1. Review the new SDK/data behavior against Google's current Data safety definitions.
2. Update `Scripts/configure_play_data_safety.py`, this file, `PRIVACY.md`, and `docs/privacy.html` together.
3. Run the manual `Google Play Data Safety` workflow.
4. Keep the successful workflow run and generated CSV as release evidence.
